Risk register

R1 · Misleading model metrics

Default checkpoint values can look like measured performance. Remove them before reporting any scores.

R2 · Data/task mismatch

Breast label schemes and Kidney segmentation/classification need explicit decisions before training.

R3 · Data leakage

Images from the same patient, study or slide must not leak across splits.

R4 · Over-sharing model parameters

Modality mismatch may cause negative transfer. Compare independent baselines with shared-encoder experiments.

R5 · Incomplete verification

Compilation is not a substitute for passing tests, and configured Docker services are not proof of deployment.

Faculty presentation brief

Suggested wording to distinguish implemented foundations from work still in progress.

What we can confidently present

Keep claims tied to inspected code and documents.

  • OncoSentinel is designed as a unified, modular research and decision-support platform for multiple cancer-imaging tasks.
  • The project defines an eight-category taxonomy and has software scaffolding for ingestion, routing, ML orchestration, RAG, explainability, uncertainty and related services.
  • The next engineering milestone is a reusable hybrid training engine and sequential model-training queue.
  • We are explicitly separating architecture completion from experimentally verified model performance.

What we should not claim yet

  • Do not claim all eight cancer models are trained.
  • Do not show placeholder checkpoint scores as experimental accuracy.
  • Do not claim clinical readiness or validated diagnostic use.
  • Do not claim a complete vector-search RAG system until the persistent index and evaluation are demonstrated.
  • Do not claim the test suite passes until the full test command completes.

Suggested one-line status

“The architecture and core service scaffolding are established; the immediate focus is reproducible model training, end-to-end validation, and evidence-backed expansion across all eight tasks.”
